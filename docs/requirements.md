# everyBuddy 桌面 Agent 应用需求文档（PRD）

> 版本：v0.1  
> 日期：2026-07-19  
> 状态：MVP 设计阶段

---

## 1. 产品概述

### 1.1 产品定位

**everyBuddy** 是一款面向开发者的本地桌面 AI 助手，基于 Electron + React 构建，核心 agent 能力由 [pi-agent monorepo](https://github.com/earendil-works/pi)（`@earendil-works/pi-coding-agent`）提供。用户可通过自然语言与本地代码仓库交互，完成代码阅读、编辑、命令执行、项目探索等任务。

### 1.2 目标用户

- 软件开发者
- 技术负责人 / 架构师
- DevOps / SRE 工程师

### 1.3 核心价值

1. **本地优先**：代码、会话、配置均保存在用户本机，敏感数据不出境。
2. **自然语言操作代码库**：通过对话完成读文件、改代码、跑命令等开发任务。
3. **可扩展的客户端架构**：MVP 仅交付桌面端，但架构为未来 WebUI、TUI、即时聊天工具客户端预留接入点。

---

## 2. 术语表

| 术语 | 说明 |
|------|------|
| AgentHost | 封装 pi-coding-agent 的独立 Node.js 子进程，负责 agent 运行时、工具执行、会话持久化 |
| Electron 主进程 | Electron 的 Node.js 主进程，负责窗口管理、系统钥匙串、启动并守护 AgentHost |
| 渲染进程 | Electron 的 Chromium 进程，运行 React UI |
| IPC 契约 | 渲染进程与主进程之间的类型安全通信协议 |
| 工作区（Workspace） | 用户选定的本地目录，agent 的所有文件操作默认限制在该目录内 |
| 破坏性工具 | 可能修改文件系统或执行系统命令的工具，如 `write`、`edit`、`bash`、`rm` |

## 3. 功能需求

### 3.1 MVP 功能清单（P0 为必须，P1/P2 为优先级递减）

| ID | 功能模块 | 优先级 | 需求描述 |
|----|----------|--------|----------|
| F1 | 对话式交互 | P0 | 支持多轮文本对话，助手回复流式展示，用户可中断生成 |
| F2 | 代码工具调用 | P0 | 复用 pi-coding-agent 工具：`read`、`write`、`edit`、`ls`；`bash`/`grep`/`find` 可用性按平台探测——Windows 的 bash 解析真实 Git Bash（避免 WSL stub），缺失时静默排除；`grep`/`find` 依赖 rg/fd，缺失时自动降级为内置 Node 实现 |
| F3 | 会话管理 | P0 | 新建、切换、重命名、删除会话；会话以 JSONL 树结构持久化 |
| F4 | 多模型支持 | P0 | 通过 `@earendil-works/pi-ai` 接入 Anthropic / OpenAI / OpenRouter 等供应商 |
| F5 | API 密钥管理 | P0 | 首次启动引导配置；密钥安全存储于系统钥匙串，不进入渲染进程 |
| F6 | 工作区选择 | P0 | 用户可选择本地目录作为 agent 当前工作目录，支持切换 |
| F7 | 工具执行确认 | P0 | 破坏性工具调用前弹窗二次确认，用户可选择“允许一次”或“始终允许本项目” |
| F8 | 全局快捷键 / 托盘 | P1 | 支持快捷键唤醒主窗口；关闭窗口时最小化到系统托盘 |
| F9 | 设置面板 | P1 | 模型选择、温度、最大 token、主题（浅色/深色/跟随系统） |
| F10 | 日志/事件面板 | P2 | 展示 agent 事件流与系统日志，便于调试 |
| F11 | 消息复制 | P2 | 支持复制单条消息、复制代码块 |
| F12 | 导入/导出会话 | P2 | 将会话导出为 JSONL，或从 JSONL 导入 |

### 3.2 功能详细说明

#### F1 对话式交互

- 输入框支持多行文本、Shift+Enter 换行、Enter 发送。
- 助手回复以流式方式展示，用户点击“停止”按钮可中断当前生成。
- 消息类型包括：用户文本、助手文本、工具调用卡片、工具结果、系统提示。
- 支持 Markdown 渲染，代码块带语法高亮与复制按钮。

#### F2 代码工具调用

- 工具调用过程可视化：展示工具名称、参数、执行状态（执行中/成功/失败）。
- 工具结果可展开查看完整输出。
- 失败工具向用户展示错误摘要。

#### F3 会话管理

- 左侧会话列表展示会话标题与最后更新时间。
- 支持右键菜单：重命名、删除、导出。
- 会话标题可由用户手动编辑，或由 LLM 根据首条消息自动生成。
- 会话数据采用 pi-coding-agent 的 JSONL tree 格式持久化，支持分支（未来可扩展）。

#### F4 多模型支持

- 用户可在设置中选择模型供应商与具体模型。
- 支持为不同供应商分别配置 API Key。
- 通过 pi-ai 的统一接口切换供应商，无需改动 agent 逻辑。

#### F5 API 密钥管理

- 首次启动若未配置密钥，展示 onboarding 引导页。
- API Key 仅在 Electron 主进程中使用，通过系统钥匙串（macOS Keychain / Windows Credential Manager / Linux Secret Service）存储。
- 渲染进程可通过 IPC 请求“设置/更新密钥”，但无法读取原始密钥。

#### F6 工作区选择

- 用户通过文件选择器选择本地目录。
- 工作区路径存储在非敏感配置中。
- Agent 的文件系统工具默认以工作区为根目录，禁止越界访问（通过主进程校验）。

#### F7 工具执行确认

- 破坏性工具分类：
  - 写操作：`write`、`edit`、删除类命令
  - 执行操作：`bash` 及任何 shell 命令
- 弹窗内容：工具名称、参数摘要、影响范围、预计风险。
- 用户选项：
  - 允许一次
  - 始终允许本次会话
  - 拒绝
  - 取消

## 4. 非功能需求

| ID | 需求 | 优先级 | 说明 |
|----|------|--------|------|
| NF1 | 安全性 | P0 | 渲染进程沙箱化、IPC 严格校验、API Key 不进入渲染进程、工具调用需确认 |
| NF2 | 可扩展性 | P0 | 架构支持未来 WebUI / TUI / IM 客户端复用同一 agent 运行时 |
| NF3 | 可维护性 | P0 | TypeScript 全栈、类型安全的 IPC 契约、单元测试覆盖核心逻辑 |
| NF4 | 跨平台 | P1 | 支持 Windows 10+、macOS 12+、主流 Linux 发行版 |
| NF5 | 离线/本地优先 | P0 | MVP 中 LLM 调用走用户自己的 API Key，agent 运行在本机 |
| NF6 | 性能 | P1 | 复杂工具执行不阻塞 UI；长任务可中断；流式响应延迟 < 500ms（网络无关） |
| NF7 | 可测试性 | P1 | 核心包具备单元测试；关键用户流程具备 E2E 测试 |
| NF8 | 可打包分发 | P1 | 可通过 Electron Forge 生成安装包，支持自动更新（未来） |

## 5. 用户旅程

### 5.1 首次启动

1. 用户安装并打开 everyBuddy。
2. 应用展示欢迎页，引导选择工作区目录。
3. 引导用户配置至少一个 LLM 供应商的 API Key。
4. 进入主界面，默认创建一个新会话。

### 5.2 日常开发流程

1. 用户通过全局快捷键或托盘图标唤醒应用。
2. 在输入框中提问，例如：“请帮我查看 src/utils 目录，并解释每个文件的作用。”
3. Agent 调用 `ls`、`read` 等工具，结果以卡片形式展示。
4. 用户继续对话，要求修改某个文件；`edit` 工具执行前弹出确认。
5. 用户确认后，文件被修改，助手展示修改摘要。
6. 用户关闭窗口，应用最小化到托盘，会话自动保存。

### 5.3 会话回顾

1. 用户在左侧列表查看历史会话。
2. 点击会话恢复上下文，可继续对话。
3. 可导出会话来备份或分享。

## 6. 边界与不在 MVP 范围

以下功能明确不在 MVP 阶段实现，但架构需预留扩展空间：

- 语音输入/输出
- 图片、视频、屏幕共享等多模态能力
- 多用户协作或云端账号体系
- 插件/扩展市场
- WebUI、TUI、即时聊天工具客户端
- 内置 LLM 模型文件（本地离线模型）
- 自动更新（仅预留配置，不实现）

---

## 7. 成功指标

1. 能完成一次本地项目的“解释代码 → 修改文件 → 执行命令”完整流程。
2. 工具执行确认机制覆盖所有破坏性操作，无绕过路径。
3. API Key 不会以明文形式出现在渲染进程或持久化配置文件中。
4. 桌面应用可在 Windows 和 macOS 上成功打包并运行。
5. 核心包（`ipc-contract`、`agent-host`、`client-core`）单元测试覆盖率 ≥ 60%。

---

## 8. 依赖与假设

### 8.1 外部依赖

- [pi-agent monorepo](https://github.com/earendil-works/pi) 的 npm 包稳定可用。
- 用户自行提供 LLM API Key。
- 用户本机已安装 Node.js 22+（开发/构建环境）。

### 8.2 假设

- 用户理解 AI 助手可能产生错误，重要操作需人工确认。
- 工作区目录下的文件修改风险由用户承担，应用仅提供确认机制。
- MVP 阶段不处理企业级审计、合规、RBAC 等需求。
